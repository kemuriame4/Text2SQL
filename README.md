    元数据如何设计存储？
        表信息
            id 表的唯一标识
            name 表名
            description 描述
            role 表角色
        字段信息
            id 字段唯一表示
            name  名字
            description 描述
            type 数据类型
            role  主外键  度量值、维度值
            table_id  表id
            alias 字段别名【列表】
            examples  示例数据
        指标信息
            id 指标唯一标识
            name 指标名称
            alias  别名
            description描述
            relevant_columns 关联字段
        指标字段的关系表    
            column_id：字段id
            metric_id指标id
        大模型生成sql语句，
            需要知道哪些表？ table_info
            需要知道表中有哪些字段？  column_info
            字段的具体取值有哪些？ examples
            行业的专业术语？  metric
            指标需要哪些字段？ 指标字段关系表

        向量数据如何存储？
            字段信息
                向量检索召回字段，知不知道字段是那一张表？
                有没有办法拿到表的信息？根据表id查询mysql数据库
                能不能查出表的主外键？根据表id查询mysql数据库的字段表
            指标信息
                向量召回了指标，根据这个信息获取到指标对应的字段
                拿到了关联字段，能不能获取字段信息和表信息、表的关联关系

            字段的向量存储保存多少个数据点？
                字段描述： 订单成交金额
                别名： 成交金额、订单金额、销售金额
                name  字段   三个别名
                StructPoint（id   v    payload）
                字段描述：存一个数据点    1
                名称： 存一个数据点      2
                别名：有多少个别名存多少个数据点  3 4 5
                负载数据为同一个数据
                数据点的id不能是字段id，不然数据点会被覆盖
            负载数据如何存储？
                是存储完整的字段信息：
                    有可能出现mysql与qdrant数据不一致问题；
                    但是保留了完整的信息，性能相对查询数据要高
                还是存储字段id
                    针对频繁修改数据，采用存储id的方式，再反向mysql查询；
                    效率相对要低一点
